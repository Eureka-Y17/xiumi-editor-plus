# 秀米公开前端分析记录

检查日期：2026-10-25。只读检查无需登录、公开发送给浏览器的页面与脚本，未获取私人稿件、未调用保存接口。本仓库不包含秀米脚本副本。

## 已观察到的事实

公开首页 `https://xiumi.us/` 引用脚本 `https://edt.xiumius.cn/scripts/app/home/ef9908.index.min.js`，检查时约 4.87 MB。文件内可以检索到 AngularJS、AMD `define(...)` 形式的模块声明，以及以下名称：

- `home/controllers/studio/showListController`、`studio.papers`：工作区图文列表相关线索。
- `depot/constants/atomConst`：原子 / 组件常量线索。
- `depot/util/atomDataSprite`：组件数据处理线索。
- `depot/util/showDataTraveller`、`depot/util/showDataVerifier`：文档遍历和验证线索。
- `contenteditable` 相关选择与粘贴处理代码。

这些名称证明公开前端包含结构化文档处理逻辑；**不能证明已掌握完整编辑器模型、写入命令或持久化机制**。首页脚本也不能视为图文编辑器全部代码。

## 如何帮助适配

静态阅读可定位文档类型、组件 ID、父子关系、原生命令和编辑事件。后续在自有登录会话内，结合页面正常操作观察实际调用链，再编写独立适配实现。尤其需要对照图片素材交换、节点移动、文档 dirty 标记、撤销与保存流程。

不应通过复制业务源码重建一个宣称完整兼容的秀米编辑器。复制页面外观、手改 DOM 或单独重放未知接口都不能证明保存可靠。构建自有编辑引擎时可以保留独立数据模型，但必须另行验证导入导出与微信显示。

## 当前结论与缺口

公开前端分析可行，能够缩小适配研究范围。当前版本仍采用只读 DOM 检查，尚未接入任何推测的私有保存接口。未完成：图文编辑页完整加载、真实文档样本、原生命令与撤销调用链、保存后重载比对及手机显示验证。

继续研究时只记录必要接口观察和独立结论；用户登录通过浏览器完成，不收集账号密码，不把认证信息、私人文章或付费模板写入仓库。

## 导出与官方插件：0.2.0 补充

用户截图显示导出页支持 Ctrl+C / Ctrl+V，并提示部分 SVG 或字体渐变无法普通复制。这支持优先消费发布用富文本，而不是只读取某个局部文字编辑框。浏览器粘贴事件可读取 `text/html`，但应以实际收到的数据为准，不能从截图推断所有组件信息都被保留。[Clipboard API](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API)

[官方「秀米插件」商店页面](https://chromewebstore.google.com/detail/%E7%A7%80%E7%B1%B3%E6%8F%92%E4%BB%B6/fifkoliiibjdpcdfcknjjcpnahhnihid?hl=zh-CN)说明它用于快速复制秀米图文到公众号，减少某些 SVG 等格式丢失，类似同步但不需要公众号授权。这不证明存在可供本项目调用的通用接口，也不证明它能接收本项目精修后的内容。本版不依赖它，不强制用户安装第二个扩展。

[秀米图文同步文档 2.0.8](https://ent.xiumi.us/)描述了向第三方平台发送 HTML 与图片、绑定用户和接收通知的流程。这是另一条官方对接路线，需要平台接收端及 app 配置与审核；它不等于开放原生组件编辑 API。本项目当前选择无服务器的本地粘贴与复制，不接入同步 app。该文档公开索引较旧，若将来采用应重新核实服务状态与要求。
