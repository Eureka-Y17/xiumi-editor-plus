# 本地编辑台开发报告 · 0.4.0

## 当前产品决定

用户反馈原生适配体验不佳后，改为独立本地编辑台，移除秀米页面注入。把文档父子结构与 PPT 式同级遮挡分开，提供普通阅读流和叠放画布两种布局。默认示例直接包含文字卡片与背景板，避免图层能力藏在特定图片模板里。

核心工具覆盖拖拽、组合、取消组合、层级、选区富文本、段落、图片、布局、样式、自动保存和工程备份。尚未完整复刻秀米的专属交互组件、模板库、字体资产与媒体功能；表格仅支持插入与单元格文字，尚无跨单元格合并。这些能力不能仅靠按钮数量宣称完成。

## 架构与操作恢复

`StudioEngine` 继承独立 HTML 适配器，统一验证锁定/结构边界并以事务保存快照。每次拖拽只在松手时提交一次；移动预览不修改文章，避免一拖产生几十步历史。组合去除重复的祖先/子层选择，维护组件顺序；画布组合以边界矩形换算坐标，拆分保留子项位置。跨容器循环、表格单元格移出、画布跨界及特殊结构修改均拦截。

`Studio` 提供结构树、直接选择、拖拽/缩放、快捷键与属性面板。`RichTextDialog` 使用独立内容编辑区，保留选区格式并在应用时清理 HTML、保留换行，再提交单次事务。IndexedDB 保存多个草稿，工程 JSON 包含组合、画布、锁定及必要样式；恢复时重新清理执行内容。历史栈最多 40 步，不跨刷新持久化。

## 交付路线选择

秀米 HTML 导入受会员限制，原生保存模型仍未可靠验证，因此不提供回写承诺。选择可落地的网页二维码预览，加可配置的公众号草稿同步。浏览器扩展地址不可直接供手机打开；可选本机服务生成随机快照链接，默认环回，显式 `--lan` 开放同一 Wi-Fi 访问，快照一小时过期并可撤销。

微信可能清理自由定位 CSS。交付副本将叠放区域和图片背景区域转 PNG，保留视觉布局，源工程不扁平化。这会使合成区域的文字、链接和互动无法继续单独编辑/点击，文档明确说明；不把截图化包装为可编辑原生组件。

公众号连接通过本机服务调用官方凭据、图片上传及新建草稿接口，凭据不进入扩展或仓库。同步幂等记录仅在服务内存，覆盖成功与失败的同内容请求，减少重复草稿。接口失败展示错误编号，不返回 token，也不自动重试可能已成功的草稿请求。

## 验证边界

自动测试包含真实扩展加载、直接拖拽/图层、组合、选区编辑、IndexedDB 刷新恢复、剪贴板 PNG 往返、实际本机二维码页面和模拟微信响应。真实公众号权限、IP 白名单、图片限制、草稿结果和 iOS/Android 微信显示仍需账号实测，不以模拟响应代替。

以下保留旧版研究历史，原生适配策略已被上述本地路线取代。

# 第一版开发报告

日期：2026-10-25（Asia/Singapore） · 版本：0.1.0 实验版

## 0.2.0 路线调整

根据用户在真实编辑页只识别到两个推荐语节点的反馈，确认旧版仅选取局部 contenteditable 的策略不足。新增候选祖先范围、手动点选、扩大及重新识别；真实页依旧只读。

用户明确选择「复制到公众号后台即可，助手作为最后一道精修工具」。新增秀米导出富文本的粘贴导入，不再将接管秀米保存作为本地精修的前置条件。用户主动 Ctrl+V 时读取 text/html，DOMPurify 清理执行内容后保留可用嵌套、内联样式和图片。在独立本地工作台编辑副本，通过 ClipboardItem 输出 HTML + 纯文本，并可下载 HTML 备份。无需后端、账号绑定或官方插件关联。

导入副本增加 `imported` 模式，复用操作和历史接口。普通单列依据静态布局识别并允许受限拆组；特殊媒体保持限制。内部标记不写入导出内容，导入拒绝外部伪造的助手标记。预览使用独立文章样式与布局隔离，远程资源按原地址加载。

这条路线编辑的是发布用 HTML，无法承诺还原原生组件模型、已经丢失的 SVG 互动或特殊字体，也不承诺回写秀米。33 项单元测试与浏览器夹具覆盖导入、整理、复制、备份和范围修复；实际公众号效果仍需手机预览。以下初版架构说明保留为历史背景。

## 问题与产品定位

用户反馈集中在复杂模板难拆分、重叠元素难选中、图片位置难交换和字体少。公开资料显示，秀米已有布局嵌套、拆分组合与重叠顺序能力，因此产品定位应是降低结构理解和操作成本。当前痛点来自项目发起者与公开教程，尚无规模化用户访谈数据，不能作为市场需求排名。

参考：[秀米发布的模板拆分教程](https://www.sohu.com/a/244484119_330573)、[布局嵌套说明](https://www.sohu.com/a/387879686_330573)、[官方模板规范](https://xiumi.us/auth/register)。这些资料说明历史能力与常见设计问题，不能取代当前版本实测。

目标用户为使用秀米制作公众号文章、需要修改复杂模板的内容运营者。第一版不构建独立公众号发布后台，不增加模板商城和字体库，不实现任意 SVG 交互编辑。

## 已实现的范围

本地编辑演示：结构树、双向选择、父子与相邻节点导航、图片素材交换、同级排序与拖拽、普通单列拆组、元素提升、同级重叠顺序、撤销重做、初始状态恢复。提供 11 个模板覆盖主要操作与拦截场景。

真实秀米：注入中文检查入口，启发式发现可见编辑区，显示 DOM 组件树、选择浮层和属性；所有写操作由适配层强制拒绝。尚未登录验证是否能识别当前编辑页面，不能宣称真实站点兼容已完成。

首版的真实编辑保存关卡未通过，因此暂停真实页面修改；演示引擎可用于验证产品交互和操作契约。发布名称必须包含「实验版」，GitHub Release 标记 prerelease。

## 架构与接口

- WXT 生成 Manifest V3 扩展，React 渲染弹窗、演示工作台及 Shadow DOM 内的面板。
- `EditorAdapter` 封装 `tree / element / capability / execute / swap / reorder / undo / redo / restore`。两种模式为 `demo` 和 `xiumi-readonly`，不允许从网页输入切换为可写模式。
- `ComponentNode` 保存会话节点标识、类型、标签、父节点与子节点。弱映射维护标识，不向正文添加定位属性。
- 所有修改先检查模式、节点有效性、特殊结构及外部变化，再记录前后快照。最多 40 次历史，执行新动作清空重做。快照恢复仅用于自有静态演示，不能直接用于秀米的框架文档状态。
- 结构识别最多 40 层、1500 个节点；修改观察采用短延时合并。选择浮层不修改正文，滚动或窗口变化后更新位置。

图片交换包括 `src/srcset/sizes/alt`，保留目标位置的 style 和父容器；图层调整按实际同级排序重新赋值，避免数值加一后仍被更高图层遮挡。拆组保留 childNodes，外壳样式损失需确认。

## UI 与数据流

浅色工作台由模板列表、文章预览、结构 / 属性面板构成，青绿色用于选中和主要动作。面板可调宽及收起，窄屏纵向展示。明确区分本地演示与真实只读模式。

选择 → 组件 ID → 适配层查找有效节点 → 能力判断 → 操作 / 确认 → 更新结构与状态。失效节点、跨容器拖动、外部内容变化和特殊组件操作被拒绝并显示说明。

## 可行性关卡与后续适配

真实站点没有可用的登录会话，保存与刷新未验证；微信公众号草稿和手机预览也未验证。这些不是自动测试能替代的内容。

公开脚本分析已发现 AngularJS / AMD、原子组件模型相关模块和秀米文档遍历工具线索，见 [分析记录](FRONTEND_RESEARCH.md)。后续应寻找原生组件移动 / 替换命令与文档变更入口，不直接改 DOM 后假定能够保存。

每项真实能力开放前，使用自有测试稿验证：修改、原生继续编辑、撤销、保存、刷新、重新进入、草稿同步、iOS / Android 微信预览。记录秀米版本、模板类型和复现步骤；不通过则保持禁用。

## 测试、发布与维护

核心语义由 Vitest + jsdom 测试，真实安装扩展的交互由 Playwright Chromium 测试。CI 执行类型检查、测试、构建和打包；截图为自动化演示证据。实际结果见 [测试报告](TEST_REPORT.md)。

不复制秀米源码、字体或模板。公开仓库使用 MIT，仅覆盖本项目自主代码；自制示例与截图可随项目分发，第三方依赖保留各自协议。无后端、无遥测、无凭据采集。

维护优先级：真实文档模型识别 → 原生图片交换与排序保存验证 → 受限拆组与图层验证 → 人工手机预览 → 按验证结果更新兼容范围。

## 0.3.0 原生协作与属性精修

背景识别改为读取计算样式，覆盖纯色、渐变及图片背景。属性与结构修改分别鉴权，保留 SVG 的普通外层可调色但不开放结构拆分。段落编辑仅替换变化文本范围，避免整段丢失链接和格式。

原生选中实验虽有调用返回，但真实测试被用户确认整篇误选、结构树不对应，判定失败并移除调用；不把返回成功记为兼容通过。结构识别改为优先活动页，过滤页面外壳、隐藏副本和透明空容器。真实推文复测与保存仍待验证。HTML 导入入口在用户账号中受会员限制，不调用其内部导入事件绕过限制。复制返回仅定位来源标签，不能承诺原稿回写。
